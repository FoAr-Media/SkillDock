# Security model
**Renderer**: `sandbox:true`, `contextIsolation:true`, `nodeIntegration:false`, devTools off when packaged, strict CSP (`default-src 'self'; script-src 'self'; style-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, baked into the built HTML; dev server uses a looser header), permission requests denied, `window.open` denied, navigation blocked. Exposes one function (`skilldock.invoke`).
**IPC**: only channels registered in `handlers.ts`; every payload parsed by zod; sender must be our window's main frame. The renderer sends ids (skill id, plan id, config file id), never trusted paths; main re-resolves them against enumerated allowlists (`resolveConfigFile`, `findSkill`, registered projects).
**Filesystem**: `safeJoin` for all downloaded/relative paths; symlinks are never followed when copying or staging; sizes/count limits (≤300 files, ≤2 MiB/file, ≤25 MiB); only user/project skills can be removed; managed files are read-only.
**Writes**: resolve symlinks first (dotfile-managed files stay links); per-file lock; backup → atomic temp+rename → verify; conflict detection via content hash; journal for crash recovery. Backups dir is 0700, files 0600.
**Secrets**: MCP secret values masked before leaving main; edits re-merge stored values; exports use `${NAME}` placeholders; GitHub token encrypted via Electron `safeStorage` (OS keychain), refused if unavailable; never in SQLite/logs/renderer.
**Approval**: starting a process or spending Claude usage requires a native system dialog shown by the main process (`nativeConfirm`), independent of the renderer; IPC schemas require `approved: true` but that flag alone authorises nothing. CLI wrappers reject values that could be parsed as options.
**Execution**: nothing from third-party content is executed by browsing or installing. MCP servers start only after an explicit approval for that action; only list calls are made, tools are never invoked. Real Claude runs (`claude -p`) need per-run approval.
**Network**: GitHub (API/raw), MCP registry, user-added catalog URLs (https or localhost only), servers the user approves testing. No telemetry.
**Scanner is advisory**: statuses are `not-inspected / inspection-completed / review-recommended / high-risk` — never "safe". High-risk installs need an explicit checkbox.
**Known gaps**: catalog signatures are displayed, not verified; no code signing/notarization of builds; the scanner is regex-based and can be evaded.
